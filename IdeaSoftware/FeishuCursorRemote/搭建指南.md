# 飞书 + Cursor + OpenClaw：从零接到遥控

目标：用飞书私聊遥控本机 Cursor，在 `F:\SelfMaj\BIdeadProj` 里读写文件并回复飞书。

这台机器上已经有一套微信遥控，工作区是 `E:\gitProj\SkillPoint`。飞书用另一个代理 `cursor-bidead`，不改微信那条链路。

```text
飞书私聊
  → @openclaw/feishu（WebSocket 长连接，无公网）
  → 本机 OpenClaw Gateway（仅 127.0.0.1:18789）
  → 官方 ACP 绑定（type=acp，agent=cursor-bidead）
  → ACPX → Cursor CLI（agent acp）
  → F:\SelfMaj\BIdeadProj
  → 文本回复回飞书
```

| 组件 | 干什么 |
|------|--------|
| 飞书 | 手机入口 |
| OpenClaw | Gateway、通道、配对。不必另配模型 API |
| Cursor | 读文件、改代码、跑命令 |
| `cursor-bidead` | 只服务飞书，cwd 固定在本仓库 |

微信插件不会解析 ACP binding，所以 SkillPoint 用了本地补丁。飞书插件会解析，这里不要去改 `process-message.js`。

不要把 Gateway 暴露到公网，不要改成 Webhook。

## 1. 合并配置

```powershell
cd F:\SelfMaj\BIdeadProj\IdeaSoftware\FeishuCursorRemote
.\kit\setup.ps1
```

`setup.ps1` 会：

1. 若插件列表里还没有飞书，安装 `@openclaw/feishu@2026.7.1`
2. 备份 `openclaw.json`，写入 `cursor-bidead`
3. 飞书通道默认 WebSocket、私聊配对、群聊关闭，并关掉文档/云盘/多维表格工具
4. `openclaw config validate`

它不登录、不重启 Gateway、不碰 `channels.openclaw-weixin`。

---

## 2. 确认 Cursor 已登录

```powershell
agent status
```

未登录时，飞书里只会看到 ACP 起不来。需要的话先 `agent login`。

---

## 3. 飞书登录

先启动 Gateway：

```powershell
$env:Path = "D:\OpenClaw\deps\node-v24.18.1-win-x64;" + $env:Path
openclaw gateway start
openclaw channels login --channel feishu
```

优先用扫码。扫码成功后，私聊会锁到你自己的 `open_id`。

国内飞书扫不出来时，改手动：

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用。
2. 复制 App ID、App Secret，贴进向导。不要把这两样写进仓库。
3. 应用能力里打开机器人。
4. 权限至少开通：接收私聊消息、以机器人身份发消息、读取消息资源。具体名称以控制台为准，向导和 `feishu_app_scopes` 会指出缺哪项。
5. 事件订阅选「使用长连接接收事件」，订阅 `im.message.receive_v1`。保存这一步时 Gateway 要在跑，并且应用凭证已经配进 OpenClaw。
6. 创建版本并发布到企业内。
7. 向导问域名选飞书，问群策略选禁用。

登录向导可能会重写 `channels.feishu` 的一部分。向导结束后再跑一次：

```powershell
node .\kit\apply-config.mjs
```

这次会补回被向导漏掉的策略，同时留下已经写入的 App ID / App Secret。

---

## 4. 配对并绑定到本仓库

手机飞书里找到这个机器人，发一条私聊。

```powershell
openclaw pairing list feishu
openclaw pairing approve feishu <配对码>
```

只批准自己。然后把你的 `ou_` 绑到 `cursor-bidead`：

```powershell
node .\kit\bind-direct.mjs --open-id ou_你的open_id
openclaw gateway restart
node .\kit\status.mjs
```

`status.mjs` 里应看到 `appSecret=yes`、`agent=cursor-bidead`、一条 `binding ... peer=direct:ou_...`。它不打印密钥。

绑定会把私聊改成白名单，并把这个 `ou_` 放进 `allowFrom`。群聊保持关闭。

## 5. 验收

飞书私聊发：

```text
目标：只读列出 F:\SelfMaj\BIdeadProj 根目录有哪些文件夹
禁止：修改文件、push、删除
```

应在几分钟内收到 Cursor 的回复。

再把 `kit\first-message.txt` 的内容发一遍。持久会话会记住工作区、目录和「改完要自动提交、不要 push」。

写入验收：让它在 `IdeaSoftware/FeishuCursorRemote/` 里加一个临时说明文件。回复里应带 `COMMITTED`，或说明脚本打印了 `NO_CHANGES`。

出站试一下：

```powershell
.\kit\send-feishu.ps1 -Target ou_你的open_id -Message "飞书遥控已接通"
```

## 6. 日常

```powershell
$env:Path = "D:\OpenClaw\deps\node-v24.18.1-win-x64;" + $env:Path
openclaw gateway start
openclaw gateway stop
openclaw gateway restart
openclaw channels status --probe
openclaw logs --follow
```

权限是 ACPX 插件上的全局项，微信和飞书共用。这台机器当前是 `approve-all`，所以飞书私聊可以改文件、跑命令。要临时收成只读：

```powershell
openclaw config set plugins.entries.acpx.config.permissionMode approve-reads
openclaw gateway restart
```

改回去用 `approve-all`。只读时，非交互会话里的写操作会被拒绝。

5 分钟内连续强杀 Gateway 达到 3 次，可能触发重启保护，通道会暂时起不来。等满 5 分钟再正常重启一次。

会话是持久的。`/reset` 会丢掉对话，不会丢掉仓库文件。

## 7. 安全

- Gateway 只监听 loopback，并使用已有 token
- 飞书只用 WebSocket，不配公网回调
- 私聊白名单，群聊关闭
- 文档、知识库、云盘、多维表格工具默认关闭
- Cursor ACP 不在 OpenClaw 沙箱里。约束靠 cwd、白名单和 `first-message.txt`
- 自动提交只 `git commit`，不 push

App Secret、Gateway token、个人 `open_id` 只留在 `D:\OpenClaw\state\openclaw.json`。

## 8. 故障

| 现象 | 处理 |
|------|------|
| `Node.js >=22.22.3` 报错 | PATH 最前面加上 `D:\OpenClaw\deps\node-v24.18.1-win-x64` |
| 飞书没回复，日志像在找模型 API | `status.mjs` 看有没有 `binding ... cursor-bidead`。没有就重跑 `bind-direct.mjs` |
| ACP 失败 | `agent status`；确认 `C:\Users\Lenovo\.acpx\config.json` 里 cursor 仍指向 `agent.cmd acp` |
| 机器人在线但收不到事件 | 开放平台事件订阅是否为长连接，且已订阅 `im.message.receive_v1`；应用是否已发布 |
| 扫码没反应 | `openclaw channels login --channel feishu`，改手动填 App ID / App Secret |
| 装了更新版本的 `@openclaw/feishu` 后起不来 | 卸掉后装回 `@openclaw/feishu@2026.7.1`。它要求 OpenClaw `>=2026.7.1`，更新的插件要求更新的 OpenClaw |
